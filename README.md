# DungeonMAIster

Documento Mestre: Motor TTRPG com IA (D&D 5e)1. Visão Geral do ProjetoObjetivo: Desenvolver um motor de RPG de mesa (TTRPG) para um jogador (Solo RPG), focado estritamente no sistema de regras do Dungeons & Dragons 5ª Edição (D&D 5e).Papel da IA: Atuar em tempo real como o Mestre de Jogo (Dungeon Master - DM), organizando a narrativa, gerenciando encontros, diálogos, e validando testes de atributos e combates com base nas regras do D&D 5e.Modelo de Distribuição: Aplicação Web Local (Roda no navegador do usuário, mas o servidor é hospedado na própria máquina, garantindo privacidade, zero lag de rede externa e facilitando expansão futura para multiplayer).2. Stack Tecnológica (Arquitetura)2.1 Backend (Motor e Lógica)Linguagem Principal: Python 3.xServidor Web: FastAPIComunicação: WebSockets (Para comunicação em tempo real e bidirecional entre o jogador e o Mestre de IA, simulando digitação contínua).2.2 Frontend (Interface do Usuário)Base: HTML5, CSS3, Vanilla JavaScript.Estilização: Tailwind CSS (via CDN inicialmente) para uma interface limpa, rápida e responsiva, dividida em painéis (Chat, Ficha de Personagem, Rolagem de Dados).2.3 Módulo de Inteligência Artificial e RAGOrquestrador de IA: LangChain ou LlamaIndex (Para criar o pipeline de pensamento do Mestre).Processamento Local (Principal): Ollama (Rodando modelos focados em roleplay e instrução, como Llama-3 ou Mistral, garantindo custo zero e execução offline).Processamento em Nuvem (Fallback): Integração com APIs externas (ex: OpenAI, Google Gemini) acionadas mediante inserção de chave API nas configurações do sistema.Banco de Dados Vetorial (RAG): ChromaDB ou FAISS.Propósito: Armazenar os manuais de regras do D&D 5e e módulos de aventuras (PDFs). A IA consultará esse banco antes de responder para evitar alucinações e aplicar regras corretamente.3. Estrutura de Pastas SugeridaPara facilitar a implementação via agentes de IA, o projeto deve seguir esta estrutura modular:meu_rpg_ai/
├── backend/
│   ├── main.py              # Ponto de entrada do FastAPI e rotas WebSocket
│   ├── ai_engine/           # Lógica do Mestre (Langchain, Prompts, Conexão Ollama/API)
│   ├── dnd_rules/           # Lógica hardcoded de D&D (cálculo de modificadores, dano)
│   └── rag_system/          # Processamento de PDFs e consultas ao ChromaDB
├── frontend/
│   ├── index.html           # Interface principal do jogador
│   ├── css/                 # Estilos customizados (se necessários além do Tailwind)
│   └── js/                  # Lógica do painel (WebSockets, atualização da ficha)
├── data/                    # Banco de dados local (Fichas de personagens, histórico de chat)
├── docs/                    # Documentação do projeto (Incluindo este GDD)
└── requirements.txt         # Lista de dependências do Python
4. Funcionalidades Principais (Roadmap de Implementação)Fase 1: Fundação do Chat (Comunicação)[ ] Configurar servidor FastAPI básico.[ ] Criar a interface HTML/JS com área de chat e campo de input.[ ] Estabelecer conexão via WebSocket.[ ] Implementar a classe AIGameMaster para receber mensagens e devolver respostas textuais simples (integrado ao Ollama local).Fase 2: O Motor RAG (Conhecimento do Mestre)[ ] Implementar script para ler PDFs de regras e aventuras.[ ] Quebrar o texto em fragmentos (chunks) e criar embeddings.[ ] Salvar os embeddings no ChromaDB local.[ ] Configurar a IA para buscar o contexto no banco de dados vetorial antes de narrar a cena.Fase 3: Ficha de Personagem e Sistema d20[ ] Criar estrutura de dados (JSON/Modelos Pydantic) para a Ficha de D&D 5e (Atributos, Perícias, HP, CA, Inventário).[ ] Implementar sistema no frontend para exibir e editar a ficha.[ ] Desenvolver o "Motor de Dados" (Dice Roller). A IA deve conseguir solicitar rolagens (ex: "Role Percepção") e o sistema de interface deve permitir que o jogador clique para rolar, enviando o resultado de volta para a IA analisar.Fase 4: Refinamento e Expansões[ ] Suporte a troca para APIs externas (Interface de configurações para inserir chave).[ ] Sistema de salvamento de sessões (Histórico do chat para a IA lembrar do que aconteceu em dias anteriores).[ ] Interface de upload de PDFs pelo frontend (Adicionar novas campanhas dinamicamente).5. Diretrizes de Prompting para o Mestre (Anotações de Design)O system_prompt da IA deve sempre reforçar:Você é um DM de D&D 5e, não um assistente virtual.Descreva os cenários usando os 5 sentidos.Nunca decida a ação do jogador por ele.Peça rolagens de dados (1d20 + modificador) sempre que o desfecho de uma ação for incerto.Baseie-se no contexto RAG fornecido para regras e descrições de monstros/cenários.
